# Independent judgment on the NOAA GFS analysis virtual validation report

My cold judgment: fix A1's values before publication, rewrite A2's comments, promote four of the seven open questions to metadata work, send one to the dataset owner, and drop two.

## 1. The two defects

### A1 — `sunshine_duration_surface`

I would select leads 1–6, changing the values at synoptic hours.

That produces one coherent contract: every timestamp contains sunshine accumulated since the preceding 00/06/12/18 UTC boundary, with lead 6 at the boundary itself. It agrees with the analysis-specific window description and removes the artificial 18,000 → 10,800 s reset. This is preferable before publication even though it changes values, because the alternative permanently exposes a semantically opaque field every sixth hour.

I would not blindly put `hour_0=False` in the shared catalog, however. `has_hour_0_values()` is documented as answering whether the source provides a lead-0 value—and SUNSD does. If another GFS virtual product needs the actual f000 record, a shared override would incorrectly suppress it there. Scope the lead-selection override and the 1–6-hour comment to the analysis product, or introduce an analysis-selection distinction instead of misrepresenting source availability.

The unresolved direction of the f000 three-hour-equivalent field does not block this choice. It actually weighs against retaining that field: the report established its 10,800 s cap but not which hours it represents. That uncertainty matters only if you keep the current values and try to describe them.

I would change my mind if:

- authoritative NOAA documentation identified the exact f000 interval; and
- the owner explicitly preferred “shortest available source lead” over consistent window semantics; or
- inspection showed that previous-cycle f006 is not actually the preceding six-hour interval at the valid time.

Until then, the report's definitive Part B statement that f000 “is a 3-hour total” is slightly stronger than its evidence. It established a three-hour-sized cap, not the interval.

### A2 — the convective-cloud pressure pair

Rewrite the comments; do not change values.

Suggested evergreen wording:

> NaN means the source does not provide a convective cloud base pressure at this cell; this can occur even when `convective_cloud_cover` is nonzero.

Use the corresponding “top pressure” wording for the other variable.

The current “near zero” explanation is too narrow: at the inspected time, missing pressures coexist with convective cover well above a defensible meaning of “near zero.” Avoid embedding 39%, percentiles, or “cloud-field edges” in static metadata; those are sampled observations, not timeless semantics.

## 2. The seven open questions

1. **Nothing.** With the A1 value fix, the unexplained f000 field is no longer exposed in this analysis dataset. Do not spend more validation-report space on it. It becomes an owner/source question only if current values are retained.

2. **Code fix.** Add `flag_values=(2,3,4,5,6)` and meanings equivalent to `very_low_potential very_low_potential low_potential moderate_potential high_potential`. Haines is an enumerated ordinal with authoritative meanings, not merely an arbitrary continuous index. NOAA gives exactly that mapping, and CF flags are intended to make enumerated values self-describing.

3. **Code fix.** Remove `standard_name="soil_type"`. CF's `soil_type` is strings or integer codes translatable through flags; interpolated fractional class numbers satisfy neither representation. The current comment admits this directly. A passing repository test does not make the metadata conformant.

4. **Code fix.** Add `standard_name="equivalent_thickness_at_stp_of_atmosphere_ozone_content"` and express the units in a CF-recognizable length unit numerically equivalent to DU, such as `10 um`; alternatively decode to metres. Do not merely add the standard name while retaining an unrecognized `DU` unit. CF explicitly identifies this quantity and permits a dimensionally equivalent scaled length unit.

5. **Dataset-owner/source question.** Do not invent a sign comment from the near-zero wind correlations. Confirm what NOAA's U-GWD/V-GWD signs mean relative to force on the atmosphere. The present CF standard names already assert a directional convention, so the real question is whether those names are justified—not whether an optional comment is absent. NOAA's table names them only as zonal/meridional gravity-wave stress fluxes and does not settle that interpretation.

6. **Code fix.** Document that zero represents a window with no sunlight and must be excluded from time-mean albedo. Do **not** set `fill_value=0` from this evidence alone: the required cross-decoder, cross-era test has not been done. If that test proves zero uniquely covers all undefined cells and never valid cells, normalize it as the declared fill; otherwise retain it and give an explicit mask instruction.

7. **Nothing.** A single geographically plausible, source-faithful maximum is not a defect or an owner decision. Cut it.

## 3. “Odd but explained” and passed checks

I see no additional confirmed defect in Part A(b), but several explanations are stronger than the evidence:

- “The GFS vegetation cycle” does not establish why field capacity and wilting point vary at the fourth decimal. Those are not obviously seasonal vegetation quantities. Call it small source variation or packing variation unless its cause was actually traced.
- One byte-identical duplicate APCP record establishes harmlessness for that file, not throughout the supported archive. Either sweep representative eras or narrow the claim.
- The soil-temperature ripple and noisy PV pairs are plausible source/model behavior, but the report did not independently establish the stated causes. They need not become findings; just avoid claiming the cause is proven.
- The packing-offset zeros and the potential-temperature unit difference are not defects. In particular, potential temperature in K is the correct CF choice.

Several PASSED headings overclaim:

- **“Source fidelity — bit-exact”** applies only to the eight probed arrays and positions, not all 272 arrays or the year. Also, decoding both the virtual store and raw GRIB with gribberish is not an independent decoder comparison. It strongly checks reference selection and transformations, but not decoder correctness. The final evidence also says snow differed by `1.1e-16`, so “bit-exact” is literally false there.
- **Completeness** establishes that expected references exist at every in-window position. The limited decode sampling does not prove that every reference in every array decodes successfully.
- **“No undeclared sentinels”** was not established archive-wide. It covered root arrays at a few positions and would miss rare sentinels, time-limited sentinels, and group-only problems.
- **“No step changes”** was established for 40 variables, not 272. This is the conclusion most directly invalidated by the abandoned drift sweep and 209 unreviewed plots.
- **Flags** were in-range at three sampled times, not demonstrably throughout the year.
- **Windowed variables** is too broad a heading for a handful of tested families—especially when SUNSD failed.
- **No quantization problem** does not follow from distinct-value counts. `no-rounding` proves this reformatter adds no rounding; it does not rule out source-GRIB quantization or visible spatial staircasing.
- The NaN and pressure-gap results are good evidence at the sampled times, but “stable across the window” should mean “stable at the window's start, middle, and end,” not exhaustive stability.

The skipped work does not affect A1 or A2. It does affect any whole-dataset conclusion about source-era drift, rare sentinels, unexpected distributions, spatial artifacts, and unreviewed variables. The missing `validation_summary.md` is not itself substantive, but the unfinished underlying coverage that would have populated it is. Geometry is reasonably established at the shared-grid level without spatial plots; meteorological plausibility for every variable is not.

## 4. Part B against the owner's rule

The largest violation is the SUNSD bullet under “Source data changes over time.” A repeating six-hour cycle is not a source change over historical time. With my recommended fix, the bullet disappears entirely. If current values are retained, the behavior belongs in variable metadata, not in any of the owner's three report categories.

Other issues:

- The seven-timestamp availability bullet is not actionable enough. It must say which product is absent at each timestamp and therefore which variable set is affected. “One or both,” followed by “46,899 carry at least one product,” leaves readers unable to select safe timestamps.
- Split the ordinary high/middle/low cloud families from the convective pair. Their missingness behavior is materially different.
- “A tenth of those empty cells have more than 11% cover” misstates the table: the percentile was calculated only among NaN cells with **positive** cover, not all empty cells.
- The albedo bullet's “about 32% of the grid at any time” extrapolates a single inspected field. Keep the masking instruction if further checks support it, but remove that universal percentage.
- The remaining structural-unavailability bullets are within the rule: land-only fields, land-or-ice fields, ice-only temperature, PV surfaces, terrain-obscured height levels, pressure-level gaps, clouds, and Haines. They describe states readers can act on.
- The two explicit-mask bullets for frozen-precipitation percentage and cloud ceiling belong exactly where they are.
- No genuine historical source-data change was established. Leave that category empty rather than filling it with SUNSD.

What may still be missing cannot be known from this report: a mask requirement or historical source transition confined to one of the 209 unreviewed variables could have escaped detection. The incomplete drift sweep and plot review prevent Part B from being presented as an exhaustive clean set.
