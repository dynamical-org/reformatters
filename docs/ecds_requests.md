# ECDS request lifecycle

The ECDS archive client preserves a queued or running request when a polling budget expires. Retrying with the same state file resumes that request, including state files marked `abandoned` by older clients. If local state is missing, submission first searches the account’s outstanding S2S jobs, following pagination, and adopts an exact matching request. An unmatched outstanding S2S job raises `EcdsAccountBusyError` without submitting or cancelling anything. An unreadable queue also prevents submission.

Archive retrievals default to one concurrent request. The queue check and submission are serialized within one Python process. **This is not a distributed account lock:** two processes or hosts can both observe an empty queue and submit. Coordinate operational archivers and historical backfills sharing an account; allow only one producer to submit at a time, with operational work taking priority. A job belonging to a different selection is never cancelled merely to make room.

After polling times out, a request whose age exceeds `maximum_request_age_seconds` is cancelled with DELETE. The client confirms a terminal status or that the job no longer exists before submitting a replacement. Failed or unconfirmed cancellation stops retrieval. At most one age-expired replacement is submitted per retrieval call; if the replacement also exceeds the limit, it is cancelled and retrieval stops. The age includes queue time and survives restarts because it comes from the original submission timestamp. The default age limit is 24 hours; the archive CLI exposes `--maximum-request-age-seconds` to adjust it. This limit is checked after each bounded polling attempt, not by a background timer.

A process or pod exiting does not cancel its server request. Preserve the work directory when possible and restart the same selection to resume it. If another selection is blocking the account, inspect its owning producer before deciding to finish or cancel it. A new process does not sweep or cancel unrelated account jobs. Expired results and server-terminal failures can still be replaced, subject to the account queue check and the existing resubmission budget.

The request age limit does not extend a pod deadline, and sequential retrieval can take longer than a parallel archive. Check completion time and account contention before changing either bound. Existing running clients keep their current behavior until restarted with the updated code.
